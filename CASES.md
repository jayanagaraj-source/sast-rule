Labels state the **expected security behaviour** of a correct rule, decided from the data flow, not from what the current rule pattern happens to match.

| Label | Class | Meaning |
|---|---|---|
| `ruleid` | TP | Real vulnerability; the rule is expected to report it. |
| `ok` | FP control | Safe code; the rule must not report it. |
| `todoruleid` | GAP | Real vulnerability the current rule cannot cover by design (language not served, API/source/sink outside the pattern, cross-file flow). |
| `todook` | KFP | Safe code the current rule's pattern is known to match (documented false positive). |
| `tg-either` | AMB | Context-dependent: reporting or not reporting are both acceptable. |
